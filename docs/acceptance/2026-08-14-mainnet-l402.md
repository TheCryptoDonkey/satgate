# Mainnet L402 acceptance — 14 August 2026

Status: **PASS**

This record covers one controlled, real-money Lightning payment against the
public Satgate service linked from the project README. It separates field
evidence from unit, integration, release and deployment checks.

## Safety envelope

- One 10-sat invoice was created for this acceptance run.
- The payer authorised at most 2 sats in routing fees.
- Only one payment attempt was made. There was no blind retry.
- The production applications held a limited Phoenixd credential and had no
  outgoing-payment permission.

## System under test

| Component | Evidence |
| --- | --- |
| Satgate | `v1.15.4`, commit `e394ef91adf903f04a0d15f23c0fe94ce3e100b6` |
| Public endpoint | `/health` returned HTTP 200 |
| Inference backend | `qwen3:0.6b` through the OpenAI-compatible chat endpoint |
| Payer | User-operated Wallet of Satoshi wallet |
| Receiver | Production Phoenixd node used by Satgate |

## Result

| Check | Result |
| --- | --- |
| Invoice amount | 10 sats |
| Wallet routing fee | 1 sat |
| Total payer spend | 11 sats, within the 12-sat authorised maximum |
| Satgate settlement state | Invoice reported paid |
| Cryptographic settlement | Returned preimage hashed to the invoice payment hash |
| Paid request | `POST /v1/chat/completions` returned HTTP 200 with an actual model response |
| Usage accounting | Estimated cost 10 sats; remaining credit 0 sats |
| Receiver accounting | Phoenixd recorded one 10-sat incoming payment and its balance increased by exactly 10 sats |
| Channel continuity | Channel identity, funding transaction and capacity were unchanged; state remained `Normal` |

The public record deliberately excludes the BOLT11 invoice, payment hash,
preimage, L402 credential, Phoenixd credentials and wallet secrets.

## What this proves

This proves one end-to-end mainnet path: a human paid Satgate's Lightning
invoice from an independent wallet, Satgate observed settlement, issued a valid
L402 credential, served paid inference, and the receiving node accounted for
the same 10 sats.

It does not prove every wallet, route, model or payment rail; sustained
availability or throughput; or an automated NWC payer flow. Those require
separate acceptance evidence.
